# 1. DB 설계 단계

![](https://imgur.com/TIGrtyA.png)  

📌DB 설계 단계는 위의 그림과 같다.  

>[!summary]
> DB설계는 실세계에 존재하는 ***추상적인 것들을 정의***하고 분석하는 단계를 지나 ER 다이어그램을 통해 ***개념적으로 표현***하고 여러 개체와 속성들의 ***관계를 나타낸 논리적인 관계모델로 표현***한다, 그 후 ***물리적인 공간에 저장할 수 있게 표현***하는 순서이다.  

1. 실세계 - **요구사항 수집 분석**
	- 실제 세계에서 어떤 시스템을 구축할 것인지에 대한 요구사항을 수집한다.  
	- 요구사항에 대해 어떤 데이터들이 필요한지, 어떤 기능들이 필요한지 분석한다.  
2. **개념적 설계**
	- ER 다이어그램을 통해 요구사항을 개념적으로 표현한다.  
3. **논리적 설계**
	- 관계모델(Relation model)을 통해 개념적 설계를 논리적으로 표현한다.  
4. **물리적 설계**
	- 실제 디스크와 같은 물리 저장장치에 데이터를 저장할 수 있도록 표현한다.  

📌 개념적 설계와 논리적 설계에서 작성하는 **ER 다이어그램**과 **Relation**을 표현하는 것은 특정 DBMS에 관계가 없다.  
📌MySQL이든 Oracle이든 설계하는 방법은 같다는 의미이다.  
📌그런데 물리적 설계는 특정 DBMS를 전제로 한 모델링이기 때문에 DBMS에 의존적이어야 한다.  

## 데이터베이스 설계 시 고려 사항

- **무결성(Integrity)**: DB에 대한 변경 연산(갱신, 삽입, 삭제)이 수행된 뒤에도 데이터 값이 만족해야 될 주어진 제약 조건을 항상 만족해야 한다.  
- **일관성(Consistency)**: 저장된 두 데이터 값 사이나 특정 질의에 대한 응답 간에 모순성 없이 일치해야 한다.  
- **회복(Recovery)**: 시스템에 장애가 발생했을 때 장애 발생 이전의 일관된 상태로 회복할 수 있는 능력을 말한다.  
- **보안(Security)**: 권한이 없는 사람이 의도적, 불법적으로 데이터를 변경, 손실, 노출시키는 것을 방지하는 것을 말한다.  
- **효율성(Efficiency)**: 응답 시간 단축, 저장 공간 최적화, 시스템 생산성 향상 등이 포함된다.  
- **확장성(Extensibility)**: 시스템 운영에 영향을 주지 않으면서 새로운 데이터를 계속적으로 추가시켜 나갈 수 있는 기법을 가져야 한다.  

## 데이터 모델의 3 요소

1. 개체(Entity)
	- 데이터베이스 분야에서 개체는 데이터베이스에 데이터로 표현하려고 하는 현실세계의 대상체이다.  
	- 개체는 현실 세계에 대해 사람이 생각하는 개념과 정보의 단위로서 의미를 지닌다.  
	- 개체는 독립적인 특성을 갖는다.  
	- 관리 대상이 되는 정보를 갖고 있는 `사람`,`사물`,`사건`,`개념` 등을 의미하고 일반적으로 명사형으로 표현한다.  

2. 속성(Attribute)  
	- 속성은 저장할 필요가 있는 개체(Entity)에 관한 정보를 의미하며, 파일 구조상 데이터 필드(항목)에 해당한다.  
	- 데이터베이스를 구성하는 최초의 논리적 단위다.  
	- 하나의 개체(Entity)는 한 개 이상의 속성(Attribute)으로 구성되고 각 속성은 개체의 특성, 상태 등을 기술한다.  

>[!example]- 예시
>![](https://imgur.com/9uUPDlI.png)  
> 위 그림은 교수번호, 성명, 전공, 소속으로 구성된 교수 개체이다.  

3. 관계(Relationship)
	- 개체 간의 연관성을 관계라고 하며, 일반적으로 동사형으로 표현된다.  
	- 개체 간의 관계 또는 속성 간의 관계이다.  

>[!example]- 예시
>![](https://imgur.com/BMRFlUz.png)  
>위 그림은 교수가 학생을 지도하는 관계다.  

- 관계의 형태
	1. `1:1`: 개체 집합 A의 각 원소가 개체 집합 B의 원소 한 개와 대응하는 관계
	2. `1:N`: 개체 집합 A의 각 원소는 개체 집합 B의 원소 여러 개와 대응하고 있지만, 개체 집합 B의 각 원소는 개체 집합 A의 원소 한 걔와 대응하는 관계  
	3. `N:N`: 개체 집합 A의 각 원소는 개체 집합 B의 원소 여러 개와 대응하고 개체 집합 B의 각 원소도 개체 집합 A의 원소 여러 개와 대응하는 관계

# DB 설계 예시

"대학교 학사 관리 시스템" DB를 구축한다고 가정한다.  

## 1. 현실 세계로부터 요구사항을 분석 및 수집

요구사항을 분석해보니 학생과 교과목에 대한 정보만 있으면 되고, 학생과 교과목에는 다음과 같은 정보들이 있으면 될 것으로 파악되었다.  

- 학생: 학번, 이름, 학년의 정보를 갖는다.  
- 과목: 학수번호, 과목명의 정보를 갖는다.  

📌예시는 간단하게 하지만, 요구사항을 파악하는 작업은 굉장히 중요하다. 
📌설계를 마쳤는데, 빠진 부분이 있거나 추가해야 할 부분이 있다면 설계를 처음부터 다시해야 할 만큼 치명적이다.  

## 2. 개념적 설계

## 4. 물리적 설계

테이블의 구조, 즉 스키마가 정리되었으니 사용하는 DBMS의 SQL로 테이블을 생성해야 한다.  

MySQL의 경우 Student 테이블을 명령어로 생성한다면 다음과 같다.  
>[!example]- MySQL Student 테이블 sql
>```sql
>CREATE TABLE Student(
>	student_no INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
>	student VARCHAR(30) NOT NULL,
>	year INT NOT NULL
>);
>```
